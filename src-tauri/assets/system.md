# 隧道使用知识

## 如何启动隧道

1. 前往 [文件下载](/dashboard/downloads) 下载适合当前系统和架构的 mefrpc/frpc 客户端。
2. 前往 [隧道管理](/dashboard/manage-proxies)，找到需要启动的隧道，点击“更多”并选择“生成启动配置”。
3. 快捷启动只能使用 ME Frp 发行的客户端；配置文件启动可以使用任意兼容 frp 客户端。
4. Windows PowerShell 启动可执行文件时通常需要在程序名前加 `./`，例如：`./mefrpc.exe -t 访问密钥 -p 隧道Id` 或 `./mefrpc.exe -c frpc.toml`。
5. Windows cmd 可直接使用 `mefrpc.exe -t 访问密钥 -p 隧道Id` 或 `mefrpc.exe -c frpc.toml`。
6. macOS/Linux 需要先进入客户端所在目录，必要时执行 `chmod +x 可执行文件名`，再运行启动命令。
7. 日志出现“启动隧道成功，您可以通过 XXX 访问您的服务”或“您可以使用 [xxx] 访问您的服务”才表示隧道启动成功。

## 一个客户端启动多条隧道

快捷启动支持多节点、多隧道模式，可用半角逗号 `,` 分隔多个隧道 ID：`mefrpc -t <访问密钥> -p <隧道ID1>,<隧道ID2>`。
配置文件启动时，一个 frpc 进程只能连接一个节点；如果多条隧道不在同一节点，需要启动多个 frpc 进程；如果都在同一节点，可以合并到同一个配置文件。

## HTTP/HTTPS 与 TCP 建站区别

- TCP 隧道可转发 HTTP/HTTPS，但访问时通常需要带远程端口，例如 `http://节点地址:远程端口`。
- HTTP 隧道用于 HTTP 服务，通常必须绑定自己的域名，访问形式为 `http://域名`。
- HTTPS 隧道用于 HTTPS 服务，通常必须绑定自己的域名，访问形式为 `https://域名`。
- HTTP(S) 隧道需要将域名解析到隧道详情中提供的解析目标；TCP 隧道一般不需要额外域名解析，直接使用分配的地址和端口。
- 中国大陆节点建站通常需要备案域名；未备案时建议改用国外节点。
- 使用 Cloudflare 代理时，SSL/TLS 模式要与隧道类型匹配：HTTP 隧道不适合 Cloudflare 的“完全/完全严格”等要求源站 HTTPS 的模式。

## HTTP 隧道 503 排查

出现 `503 Service Unavailable` 时，优先检查：

1. 访问域名是否与隧道绑定域名完全一致，`example.com` 和 `www.example.com` 是不同域名。
2. 域名 DNS 是否解析到隧道所在节点，DNS 修改可能需要等待缓存刷新。
3. 本地 Web 服务是否已启动，且在运行 frpc 的机器上能通过本地 IP 和端口访问。
4. 隧道配置中的本地 IP、本地端口是否填写正确。
5. HTTPS 隧道访问时是否使用完整 `https://` 前缀；只创建 HTTPS 隧道时，用 HTTP 访问可能出现 503。
6. 仍无法排查时，可尝试更换节点。

## 常见场景隧道类型建议

- Web 网站/API：优先使用 HTTP 或 HTTPS 隧道；如果不想绑定域名，也可以使用 TCP 隧道并带端口访问。
- SSH：使用 TCP 隧道，本地端口通常为 `22`，连接格式为 `ssh -p <远程端口> 用户名@节点地址`。暴露 SSH 前建议禁用密码认证、使用密钥登录并设置强安全策略。
- RDP 远程桌面：使用 TCP 隧道，本地端口通常为 `3389`；如需更贴近远程桌面连接状态显示，可在同一节点额外创建远程端口相同的 UDP 隧道。
- Minecraft Java：使用 TCP 隧道，本地端口通常来自 `server.properties` 的 `server-port`，局域网联机端口以游戏聊天提示为准。
- Minecraft Bedrock：使用 UDP 隧道，本地端口通常为 `19132`。
- Minecraft Java 若要隐藏端口，可配置 SRV 解析；基岩版不支持 SRV 解析。

## 本地服务连接错误

如果日志提示“连接到本地服务 [x.x.x.x:xxx] 错误”，通常表示隧道已经连接节点，但 frpc 无法访问你填写的本地地址或端口。请检查本地服务是否启动、本地监听端口是否正确、防火墙是否阻止访问，以及本地 IP 是否应填写 `127.0.0.1`、局域网 IP 或 `::1`。
